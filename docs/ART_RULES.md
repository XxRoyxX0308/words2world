# 美術規則：讓場景不像「agent 做的」

這份文件是兩個階段共用的判斷標準。每一條都來自實際做壞過的場景：先寫「為什麼會壞」，再寫「怎麼做才對」，最後是可以檢查的數字。

---

## 1. 物件要拆到「能單獨拿起來」為止

**為什麼會壞**：把「放著電腦的書桌」當成一個物件生成，TRELLIS 會把桌面、螢幕、鍵盤融成一塊；它無法重新擺放、無法在別處重用，近看就是一團。場景也因此只有少數幾個大塊，看起來空。

**規則**：現實中能單獨拿起、移開、替換的東西，就是一個獨立的 library item。

| 一組東西 | 至少拆成 |
|---|---|
| 工作桌 | 桌子、椅子、螢幕或筆電、主機、鍵盤、滑鼠、檯燈、馬克杯、紙堆、筆筒、便利貼（decal）、耳機、線材 |
| 打開的衣櫃 / 鐵櫃 | 櫃體（開門變體）、掛著的衣服 2–3 件、折好的衣物、鞋盒、帽子；門內側的照片與便條是 decal 或 slab |
| 書架 | 書架本體、書（3–5 種顏色 / 厚度，用 `arrays` 排）、書擋、盒子、小擺飾、相框 |
| 廚房流理台 | 檯面櫃、水壺、鍋、砧板、刀架、調味罐 ×3、抹布、碗盤堆、蔬果 |
| 壁爐角 | 壁爐（建築）、柴架、木柴堆（單根木柴 2–3 種用 `arrays`）、火鉗組、風箱、地毯、搖椅、毛毯 |

**數字**：一張工作桌 8–15 件；一個有人住的房間 60–150 個實例（40–90 種 item）；一個戶外小區域 30–80 個實例（不含植被）。少於這個量，房間一定顯得空。

**生成時**：每件小物用自己的真實尺寸（`size`），tier 用 `small`；不要在 prompt 裡描述它放在哪裡或旁邊有什麼。

## 2. 每個家族都要有變體

**為什麼**：同一張椅子出現 6 次會被一眼認出；而變體（開 / 關、新 / 破、空 / 滿、顏色、大小）讓重複的物件看起來像真的被使用過。

**規則**：
- library 的路徑是 `<category>/<family>/<id>`；同一個家族的變體放在同一個 family 資料夾。
- 主要家族（家具、容器、門窗附件、車輛、植物）至少 2–3 個變體；小雜物（杯子、書、罐子）用顏色 / 形狀變體。
- 變體用 `variant_of` + `edit`：以父物件**已選定的 2D 圖**當參考圖，讓 FLUX 只改指定的部分（「同一個櫃子，兩扇門打開 90 度，裡面的層板是空的」）。這樣材質與造型保持一致，再各自做 TRELLIS。
- 開門 / 打開的變體一定要另外列出「要放進去的內容物」（第 1 節），而且內容物是獨立物件。
- 做了用不到沒有關係；變體是給組場景的人挑的。

## 3. 先看概念圖，再決定放什麼

**為什麼**：agent 會列出「合理」的物件，但擺出來是整齊地貼牆一圈、中間空著，沒有聚落、沒有層次、沒有故事。圖像模型對「一個角落通常長什麼樣」有更好的直覺。

**規則**：
- 每個**小空間**（一個房間、一面牆、一個角落、門廊、一段小徑）先用 `w2w.py concept` 生成 2–4 張概念圖，不是整個世界一張。
- 建造階段已經有雛形時，把引擎截圖當 `--ref` 一起送進去：「這個房間，沿著後牆加上掛滿東西的層架和一張工作台」。概念圖會在現有格局上補細節。
- 看圖後寫下**取用了什麼**（不是照抄）到 `plan/spaces/<space>.json` 的 `concepts[].takeaways`：物件的聚落方式、高低層次、哪裡留白、光從哪裡來、主要的顏色。
- 從概念圖拆出 item 清單（第 1 節的拆法）。需要時用概念圖本身當 `refs` 生成單一物件（「把這張圖裡的搖椅單獨畫出來，白底」），風格會一致。
- 建造時先放**佔位物**（尚未做好的 item 會自動變成洋紅色的 `TEMP_<item>` 方塊），讓下一個 agent 一看就知道這裡打算放什麼。

## 4. 建築不能是盒子

**為什麼**：一面平牆 + 一個洞 + 一片屋頂，就是「方塊屋」。真實建築的每個交界處都有東西：基座、框、簷、角、接縫、管線。

**每棟建築的檢查清單**（`architecture.json`）：

| 部位 | 至少要有 |
|---|---|
| 牆底 | 基座（`plinth` 或 `foundation` 石材），與地面之間有碎石或 `chunks` |
| 牆身 | 不是單一平面：圓木（`logwall`）、雨淋板（`siding: lap`）、板條（`board_batten`）、或壁柱（`pilasters`）/ 腰線（`belts`） |
| 牆頂 | 簷口（`cornice`）或屋簷下的椽尾（`rafter_tails`） |
| 開口 | 每個門窗都有框（`frame`）、窗台（`sill_board`）、必要時楣（`lintel`）、窗格（`mullions`） |
| 轉角 | 角板（`corner_boards`）、圓木交錯出頭（`overhang` + `course_offset`）、或石砌轉角 |
| 屋頂 | 挑簷（`overhang`）、封簷板與山牆封板（`fascia`）、屋脊（`ridge_cap`）、有厚度的瓦 / 木瓦（`shingles`） |
| 附屬 | 煙囪、雨槽與落水管（`pipe`）、門廊（`slab` + `beam` 柱 + `railing` + `stairs` + 棚頂） |

- 沒有想法時，對這棟建築的外觀生成概念圖，照著拆部件；看別人怎麼處理交界處。
- 每次 `w2w.py arch` 後 Read `build/out/arch/preview_<building>.png`，用上表逐項對照。
- 室內也一樣：踢腳板、天花樑、門框內側、壁爐、裸露的管線或電線槽。

## 5. 去塑膠感：貼花要多、要放在對的地方

**為什麼**：乾淨的材質在均勻光下就是塑膠。真實表面在「水會流過、手會碰到、灰會積」的地方會變色。

**規則**：
- 每種環境至少 8–15 種貼花：水痕（直條）、泛鹼 / 白華、苔痕、煤煙、手印 / 摩擦痕、地面污漬、灰塵堆積、刮痕、裂縫、落葉（matte）、紙張 / 便條 / 照片（matte）。
- 用 `decal_rules` 對建築錨點批次放置，再手放重點：

| 錨點 | 放什麼 |
|---|---|
| `wall_base` | 濺泥、苔、泛鹼、潮痕 |
| `wall_corner` / 接縫 | **大面積**的水漬、裂縫、霉斑：蓋住直角交界，眼睛就不會停在方塊邊緣 |
| `under_window` | 直條水痕 |
| `door_frame` / `door_floor` | 手印、磨損、踩踏髒污 |
| `wall_top` | 屋簷下的煤煙、蜘蛛網、雨水痕 |
| `floor_edge` | 牆邊積灰 |
| `chimney_base` / `foundation` | 煤灰、苔、濕痕 |

- **數字**：室內每個房間 15–40 張、建築外牆每面 6–15 張、門口與走道最多。`budget.json` 會列出數量。
- 貼花的形狀要稀疏、邊緣淡出；重疊兩三張比一張大的自然。

## 6. 去重複：材質 + 幾何一起處理

**為什麼**：同一張無縫貼圖鋪滿一整面平牆，2 m 一次的重複一定看得出來；只靠貼圖再怎麼調都救不了一面沒有任何打斷的牆。

**材質端**（`surface` item）：
- `tile_m` 依真實尺寸：圓木 1 m、木板 0.5–1 m、石牆 1.5–2 m、地形 3–4 m。
- `layer2`：同材質的第二個版本（更髒、長苔、不同批次）以世界座標的大尺度遮罩混入，`layer2_amount` 0.25–0.4。
- `macro`：世界座標的亮度與粗糙度變化（室內 0.12–0.18、戶外大面積 0.2–0.3）。
- `grime`：建築的頂點色會在牆基與轉角變暗變粗；預設 0.6。

**幾何端**：任何連續 3 m 以上的平面都要被打斷：壁柱、腰線、管線溝槽與管子、簷口、窗、掛件、層架、`chunks` 碎塊吃掉牆與地的交界。

**檢查**：每張審查截圖裡，找一面最大的牆或地面；如果看得出重複圖樣或 3 × 3 m 沒有任何東西，就要補。

## 7. 地形與植被

植被和地形由 agent 做（`build/terrain.json` → `w2w.py terrain`），不是留給使用者。

- **地形**：基礎 fbm 起伏 + `ridges`（遠景山脊，給天際線）+ `carve`（溪溝）+ `flatten`（建築基地，留 6–10 m 緩坡）+ `paths`（小徑：下陷、泥土層）。
- **植被分層**，每層一個 `foliage` 項目，數量級參考（每 100 m²）：

| 層 | item | 密度 / 間距 |
|---|---|---|
| 樹冠 | 2–4 種樹 + 1 種枯樹 | 0.5–1.5 棵，`min_dist` 4–6 m，`noise` 讓林地有疏有密 |
| 林下 | 小樹、灌木 2–3 種 | 2–5 株，`min_dist` 1.5–2.5 m |
| 地被 | 草叢、蕨類、野花（`card`） | 50–200 叢，建築與小徑附近用 `area` 限制，`align: 1` |
| 散物 | 石頭、樹樁、倒木、樹枝、松果 | 2–8 件，`align: 1`，`sink` 0.2–0.4 |

- 建築與小徑要用 `avoid` 讓出空間；但建築腳下要有過渡：碎石、高草、蕨類貼著基座長。
- TRELLIS 對樹的細枝葉效果差：樹做成「厚實的整體造型」（prompt 寫 dense foliage mass, chunky solid silhouette），草、蕨、花用 `card`。

## 8. 光線與後處理（參考值）

| 光源 | 數值 |
|---|---|
| 晴天太陽 | 75 000–100 000 lux，5500–6000 K；黃昏 10 000–30 000 lux，3500–4500 K |
| 陰天 | 10 000–20 000 lux，6500–7500 K |
| 油燈 / 燭光 | 100–400 lm，1800–2200 K |
| 住宅暖光燈泡 | 800–1 600 lm，2700–3000 K |
| 壁爐火光 | 1 500–3 000 lm，1900 K，點光源 `source_radius` 0.3 |
| 曝光 | 室內 EV 3–7、戶外晴天 EV 12–15；`post.exposure` 要涵蓋場景 |

- 三層光：主光（太陽或主要燈具）、補光（Lumen + 天空光，自動）、重點光（窗邊、桌燈、火光；開陰影）。
- 每個空間有陰影的燈 ≤ 4。
- Bloom 0.3–0.4、AO 0.5、vignette 0.2–0.3、grain ≤ 0.05、高度霧 density 0.01–0.03（林間可到 0.04，`volumetric` 做光束）。
- 截圖太暗太亮先調燈與曝光範圍，不要靠後處理硬拉。

## 9. 數值限制

| 項目 | 規範 |
|---|---|
| 基色亮度 | sRGB 30–240；飽和度 ≤ 0.85（烘焙會自動夾） |
| 貼圖密度 | hero 1024 px/m、prop / small 512 px/m、表面材質 ≥ 512 px/m |
| LOD0 面數 | 小物 2k–10k、家具 10k–40k、主角 40k–80k（Nanite 可更高） |
| 每個空間 | 實例 ≤ 1500、LOD0 三角面 ≤ 1.5M（Nanite 之外）、貼花 ≤ 80、半透明物件 ≤ 40 |
| 單位與座標 | 公尺；+X 東、+Y 北、+Z 上；物件正面朝 −Y；道具原點在底部中心、`slab` 在背面底邊 |
